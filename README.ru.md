# weather-monitor

Один дашборд, который отвечает на вопрос «сегодня всё спокойно или нет?» — погода, магнитные бури, землетрясения, новостной фон и рынки в одном интегральном индексе. [**Живое демо →**](https://puginanatoly-stack.github.io/weather-monitor/) (нейтральный город-плейсхолдер, без истории)

## Что делает

Каждый день (GitHub Actions, раз в сутки) собирает данные из десяти бесключевых/бесплатных API, считает один взвешенный **индекс активности**, рендерит сайт из 4 вкладок — и, если что-то превысило порог, шлёт уведомление в Telegram.

- **Погода** — OpenWeatherMap (текущая + прогноз)
- **Космическая погода** — NOAA SWPC (Kp/Ap-индекс, солнечный ветер, вероятность авроры) + резонанс Шумана (best-effort, честно помечается, когда данные не свежие)
- **Природные события** — NASA EONET (штормы/пожары/лёд) + USGS (значимые землетрясения)
- **«Цифровой шум»** — частота публикаций в RSS-лентах BBC / Google News / Al Jazeera / RIA Novosti как косвенный индикатор
- **Рынки** — дневное % изменение по 5 базовым тикерам (S&P 500, VIX, MOEX, USD/RUB, EUR/USD) через Yahoo Finance chart API

Дизайн вдохновлён sungeo.net — earth-tone палитра, кольцевой gauge, статус-бейджи.

### Кейс Шри-Ланки

Отдельный, независимый индекс отслеживает **опасность для конкретной прибрежной точки** — те же самые фиды EONET/USGS, гео-отфильтрованные по радиусу (землетрясения в радиусе 2500 км не старше настраиваемого возрастного порога, штормы — 1500 км), с собственным взвешенным скорингом (`compute_sri_lanka_index` в `composite.py`). Начиналось как личный мониторинг риска для места, которое небезразлично автору, и осталось как наглядный пример ловушки: устаревшее, но формально ещё «в окне» событие может неделями держать индекс на одном значении, пока не выпадет из окна само (см. фикс с возрастным порогом, `SRI_LANKA_QUAKE_MAX_AGE_DAYS`, задокументированный прямо в коде). Всегда виден в уведомлении вместе с температурой воды/воздуха и ветром для побережья, независимо от того, сработал ли триггер — см. [Автоматизацию](#как-устроена-автоматизация-githubworkflowsdaily-checkyml) ниже.

Логика скоринга/фильтрации не привязана именно к Шри-Ланке — замена координат и радиусов в `sources.py` перенаправляет её на любую прибрежную точку.

## Локально

```bash
pip install -r requirements.txt
export OPENWEATHERMAP_API_KEY=...   # openweathermap.org/api, бесплатный тариф
python build.py "Pekin,CH"           # или любой другой город
```

Открой `index.html` в браузере.

## Источники данных (все без ключа, кроме OpenWeatherMap)

| Источник | Что даёт |
|---|---|
| OpenWeatherMap | текущая погода + прогноз |
| NOAA SWPC | Kp/Ap-индекс, солнечный ветер, аврора |
| Schumann Resonance Live | резонанс Шумана (неофициальный источник, честно помечается, когда данные не свежие) |
| NASA EONET | открытые природные события (штормы — источник для индекса опасности побережья) |
| USGS | значимые землетрясения, отфильтрованные до недавнего окна (источник для индекса опасности побережья) |
| Open-Meteo / Open-Meteo Marine | температура воздуха, ветер, температура воды у побережья |
| BBC / Google News / Al Jazeera / RIA Novosti (RSS) | «цифровой шум» — частота публикаций как косвенный индикатор |
| Yahoo Finance chart API | S&amp;P 500, VIX, MOEX, USD/RUB, EUR/USD — дневное % изменение |

## Как устроена автоматизация (`.github/workflows/daily-check.yml`)

Этот репозиторий публичный и хранит только код — ни город, ни история запусков сюда не коммитятся (см. `.gitignore` и docstring в `build.py`/`history_sync.py`): публичная git-история, растущая по расписанию, тихо палила бы геолокацию и паттерн активности. Поэтому:

1. **История** (`data/history.jsonl`) синхронизируется с отдельным приватным репозиторием через `history_sync.py` (pull перед сборкой, push после) — сюда, в публичный репо, она не пишется.
2. **Сгенерированные HTML-страницы** нигде не коммитятся — это просто разовый вывод одного прогона, не персистентный сайт. (Папка `demo/` — единственное осознанное исключение, см. ниже.)
3. **Условие алерта** (`notify.py`): по умолчанию (`NOTIFY_MODE=always`, settled-режим) уведомление в Telegram уходит при каждом прогоне независимо от триггера — блок опасности побережья виден в нём всегда. Если `NOTIFY_MODE=condition` выставлен явно, отправка только когда сработал триггер: интегральный индекс ≠ «Спокойно», ИЛИ рыночная волатильность/новостной шум заметно (&gt;1.5×) выше исторического среднего (только когда истории накопилось достаточно), ИЛИ индекс опасности побережья ≠ «Спокойно» — землетрясение с магнитудой ~M5.75+ в радиусе 2500 км за последние дни, или активный шторм в бассейне.

### Секреты репозитория (Settings → Secrets and variables → Actions)

| Секрет | Назначение |
|---|---|
| `OPENWEATHERMAP_API_KEY` | ключ погоды |
| `WEATHER_CITY` | город, например `Pekin,CH` — не хранится в коде |
| `HISTORY_PUSH_TOKEN` | GitHub PAT с правом записи в приватный репо истории |
| `TELEGRAM_MOTION_BOT_TOKEN` | токен Telegram-бота для алертов |
| `TELEGRAM_MOTION_CHAT_ID` | куда слать алерт |
| `NOTIFY_MODE` | необязательный; `always` (по умолчанию, если не задан) или `condition` — см. раздел выше |

## Папка `demo/` и GitHub Pages

`demo/` — разовая, закоммиченная сборка для нейтрального города-плейсхолдера (Лондон) — единственное осознанное исключение из «сгенерированное не коммитим», именно потому что не несёт ни реальной локации, ни истории. `.github/workflows/deploy-pages.yml` публикует её на GitHub Pages при каждом пуше в `demo/` — это отдельный workflow от `daily-check.yml`, он никак не касается реальной автоматизации. Обновить демо после правки вёрстки: `python build.py` (без аргументов → город-плейсхолдер по умолчанию), скопировать 4 HTML-файла в `demo/`, закоммитить.

## Файлы

- `sources.py` — сбор данных со всех источников
- `moon.py` — фаза Луны, чистый расчёт, без API
- `composite.py` — интегральный индекс активности (нормализация + взвешенный блендинг) + отдельный индекс опасности побережья
- `charts.py` — SVG line/bar/ring-графики
- `templates.py` — общий каркас страницы (навигация, CSS)
- `pages.py` — тело каждой вкладки
- `build.py` — точка входа: собирает данные, считает индекс, пишет историю + сводку, рендерит 4 HTML-файла
- `history_sync.py` — pull/push `data/history.jsonl` из/в приватный репозиторий
- `notify.py` — проверяет условие алерта, шлёт в Telegram
- `.github/workflows/daily-check.yml` — расписание + шаги
- `.github/workflows/deploy-pages.yml` — публикует `demo/` на GitHub Pages
